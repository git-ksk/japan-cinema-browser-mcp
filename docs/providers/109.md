## 2026-08-13時点の公式公開導線

### 劇場一覧

公式トップ:

```text
https://109cinemas.net/
```

トップページの「109シネマズの劇場」ブロックに、各劇場への公開linkが表示されています。

例:

```text
https://109cinemas.net/kohoku/
https://109cinemas.net/nagoya/
https://109cinemas.net/premiumshinjuku/
```

adapterはこのvisible linkから得たslugだけを劇場IDとして採用します。劇場名からslugを生成・推測しません。

### 劇場ページ / 日付指定

通常館の例:

```text
https://109cinemas.net/kohoku/
```

劇場ページの「上映スケジュール」には日付controlがあり、公開済み日付は次のような明示hrefを持ちます。

```text
https://109cinemas.net/kohoku/schedules/20260813.html?theater_code=13
```

プレミアム新宿ではquery形が通常館と異なることを確認しています。そのためadapterは `theater_code` 等のquery仕様を一般化せず、rendered public UIに表示されたhrefをそのまま採用し、遷移後も同一path/queryかを再検証します。

未公開日付はUI上に日付labelが見えてもhrefがない場合があります。hrefがない日付についてrouteを生成しません。

### 上映ページで確認したvisible semantic

公開schedule page上で以下を確認しました。

- 対象日付
- 作品名
- 上映開始 / 終了時刻
- シアター番号
- `2D`
- IMAX / 4DX / SCREENX / ULTRA 4DX等の上映方式
- `字幕` / `吹替` および `SUB` / `DUB` 表示
- `空席あり`
- `残席わずか`
- `満席`
- `販売終了または販売開始前`
- `販売開始前`
- 購入導線

read adapterはこのうち、劇場・日付・作品・時間・screen・format・language・availabilityだけをcompact structured factへ変換します。

availabilityは既存TOHO/AEON schemaに合わせます。

- `残席わずか` / `残りわずか` → `limited`
- `満席` / `完売` / `売り切れ` → `sold_out`
- `販売終了` / `販売開始前` → `unavailable`
- `空席あり`、または制約を示す明示表示なし → `unknown`

`空席あり` から残席数を推測しません。

## Render完了判定

SPA/遅延renderを前提に、固定sleepだけで結果を返しません。

- 劇場一覧: theater marker + boundary + reviewed count範囲のvisible theater links
- 劇場ページ: theater identity + schedule section + explicit date links、または明示empty state
- schedule page: date heading + showtime rows、または明示empty state

を短いbounded pollで確認します。

Chrome process / CDP targetは既存runtimeを再利用し、providerごとにbrowserを再起動しません。

## Read AdapterのFail-Closed条件

以下では部分結果を推測せず停止します。

- 公式rootの劇場ブロックが識別できない
- 劇場数がreviewed範囲から大きく外れる
- theater linkが `https://109cinemas.net/{slug}/` のreviewed shapeから外れる
- lookalike domain / credentials付きURL / non-default port
- theater queryが一意に解決しない
- 劇場pageのhostname/pathが解決済みtheaterと一致しない
- 劇場identityがrequested theaterと一致しない
- visible date labelと明示schedule routeの日付が食い違う
- schedule hrefのtheater slugがrequested theaterと異なる
- navigation後のschedule path/queryが明示hrefから変化した
- schedule headingの日付がrequested dateと異なる
- page titleのtheater identityがrequested theaterと一致しない
- 1つのDOM groupに複数time rangeが残り分離不能
- showtimeをmovieまたはscreenへ一意にbindingできない
- recognizable rowが0件なのに明示empty stateもない
- CAPTCHA / anti-bot challenge等をruntimeが検出した

missing dateは、劇場ページに他のexplicit date routesが正しく存在する場合に限り `dateAvailable=false` として返します。hrefのない日付からrouteを推測しません。

## 購入導線の扱い

劇場ページには `オンラインチケット購入`、上映回には購入導線が表示されます。

Phase 1 read adapterはこれらをclickしません。

- `seatMap=false`
- `seatSelection=false`
- `checkoutPreparation=false`
- `purchaseSubmission=false`

を維持します。

generic `click_cinema_control` / sensitive-data guard / purchase gateも既存のままで、109 adapterのために弱めません。

## 利用規約 / サイトポリシー確認

2026-08-13に以下を確認しました。

- 109シネマズ公式 `サイトポリシー`
- そこから参照される株式会社東急レクリエーション `サイトポリシー`
- 109シネマズ公式 `チケット購入方法`

サイトポリシーではWeb素材の著作権・利用条件等が定められているため、本プロジェクトはraw HTML / full DOM /画像等を保存・再配布せず、ユーザー要求時に必要なvisible semantic factsだけを一時的に扱います。

購入方法では購入フロー内で利用規約・注意事項への同意が必要とされています。Phase 1 read adapterは購入フローへ入らず、その同意controlも操作しません。

seat/checkout/purchase capabilityを検討する前、またはmaterialなautomation surface変更時には再レビューします。

## 次の段階

109追加によりTOHO / AEON / 109の3社で `theaters=true / showtimes=true` が揃います。

次はprovider固有型をそのまま横断結合せず、共通 `Theater` / `Showtime` schemaを先に定義します。

整理が必要な差分:

- theater ID / aliases / canonical display name
- `dateAvailable` / `availableDates`
- start/end timeの必須性
- format vocabulary
- language
- screen
- availability 4値の共通意味
- source URL / provenance
- movie titleのprovider表示差
- provider fan-out上限 / partial-provider failureの扱い

その上で、オンデマンド・bounded fan-outの `find_showtimes` を追加します。中央showtime DBやbackground crawlは導入しません。

## Phase 3 Seat Intelligence Discovery — 2026-08-17

Phase 3 Discoveryでは、109シネマズ港北の現行scheduleを確認した後、追加のbounded validationでrendered public UIに明示されたshowtime hrefをそのまま利用してlive seat-map surfaceへ進みました。座席自体は一切クリックしていません。

公式公開情報から確認できた点:

- 購入手順はshowtime選択後に購入枚数分のseatを選択して`次へ`
- 詳細なseat mapを確認するpublic UIがある
- seat holdは10分と明記
- 非会員は`入会せず購入に進む`ことができる
- 港北の施設UIはstandard / Executive / Pair / wheelchair seatを区別し、theaterごとのseat mapを公開

追加validationで、10分timerはseat-map entry直後から表示されることが判明しました。一方で画面は`選択座席 0／8席`を明示し、同一showtimeを独立2 browser sessionで開いた比較でも223 seat / selected 0 / unavailable 11が一致し、per-seat state差分は0でした。したがってentryはtimed purchase/session contextを作りますが、entryだけでseat holdやavailability mutationを起こす証拠はなく、むしろ起こさない強い実測証拠があります。

109はTOHOに次ぐread-only candidate（#35）ですが、v0.3.0 first scopeは広げず `seatMap=false / seatSelection=false`を維持します。seat activationは引き続きmutating boundaryです。
